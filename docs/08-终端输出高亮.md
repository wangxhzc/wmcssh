# 终端输出高亮

## 参考资料

2026-11-03 查阅以下公开资料，参考其识别对象与状态语义，在客户端实现内置规则，
无需在远端安装 grc，也不修改远端输出或配置文件。

- [grc 规则目录](https://github.com/garabik/grc/tree/master/colourfiles)：
  `conf.log` 的日志时间、进程/IP、HTTP 状态；`conf.ipaddr` 的地址、MAC 和链路状态；
  `conf.ss` 的连接状态；`conf.systemctl` 的服务状态；`conf.kubectl` 的容器状态；
  `conf.ls` 的权限；`conf.df` 的容量与使用率；`conf.ping` 的延迟和丢包。
- [GNU ls 输出格式](https://www.gnu.org/software/coreutils/manual/html_node/General-output-formatting.html)：
  `ls --color` 与 `LS_COLORS` 是远端原生文件类型着色机制，优先保留。
- [systemctl 手册](https://man7.org/linux/man-pages/man1/systemctl.1.html)：
  active、inactive、failed 与过渡状态的含义。inactive 不直接视为故障。

## 内置规则

配色集中在 `src/features/terminal/outputHighlight.ts` 的 `highlightColors`。
红色表示错误，黄色表示警告或待处理状态，绿色表示成功，青色表示网络/一般信息，
蓝色用于路径/链接，中性灰用于端口、时间、容量和数字等元数据，降低密集输出的彩色干扰。
颜色属于本应用约定，并非 Linux 统一标准。

| 类别 | 覆盖示例 |
| --- | --- |
| 提示符 | `[root@host ~]#`、`user@host:/var/log$`；root 用户名红色，目录蓝色 |
| 日志级别 | ERROR、ERR、FATAL、CRIT、ALERT、EMERG、WARN、NOTICE、INFO、DEBUG、TRACE |
| 常见错误 | permission denied、connection refused、no space left on device、command not found、timed out |
| 服务/容器 | active、running、ready、enabled、inactive、stopped、Pending、CrashLoopBackOff、OOMKilled；kubectl 常见 Pod 行的就绪比例 |
| 网络状态 | UP、DOWN、NO-CARRIER、LISTEN、ESTAB、TIME_WAIT、SYN_SENT、TCP、UDP |
| 网络地址 | IPv4/IPv6、CIDR、IPv6 zone、MAC；校验地址范围和前缀位数 |
| 组合端点 | `10.0.0.1:8080`、`10.0.0.1:8080/api`、`10.0.0.1/health`、`[::1]:8080/api`、`localhost:8080/api`、`host.example.com:8080/api`；地址青色、端口灰色、路径蓝色，校验端口范围 |
| 日期时间 | ISO 日期时间、syslog 月份日期、Last login 英文日期、独立日期/时分秒 |
| 文件信息 | 绝对路径、相对路径、家目录路径、行首 ls 权限串 |
| 协议 URL | 通用 `协议://` 结构，覆盖 HTTP(S)、FTP(S)、SOCKS4/4a/5/5h、SSH/SFTP、WS(S)、git+ssh、Redis 等；协议与端口灰色、主机青色、路径/查询蓝色，保留默认端口原文 |
| 服务名/元数据 | .service/.socket/.timer 等 unit、UUID、进程名[PID]、十六进制数 |
| HTTP | 请求方法、HTTP 响应/访问日志和 status/status_code/http_code 键后的状态码 |
| 容量/速度/耗时 | 1.2MiB、100G、12MB/s、64 bytes、1.25 ms |
| 百分比 | 普通百分比青色；df 和 usage/used/utilization 后的使用率低于 80% 绿色、80% 起黄色、90% 起红色 |
| ping | 0% packet loss 绿色，非零丢包红色；TTL、icmp_seq、延迟 |
| 键值 | pid/ppid/uid/gid/port 的数字，key=true/false/yes/no/null |

## 行为与限制

- 默认关闭，沿用现有设置持久化并应用于已有和新建终端。
- 只应用显示层装饰，不插入 ANSI 序列，复制文本保持原样。
- 协议 URL 使用平台 URL 解析器校验，按原文位置着色；识别 FTP/SOCKS 等不代表允许点击打开，链接激活仍仅限现有 HTTP(S) 策略。
- 规则命中包含已有前景色、背景色、反色或隐藏属性的单元格时跳过，优先保留远端样式。
- 只处理可见物理行；每行最多 32 处、合计最多 300 处，优先覆盖底部最新输出。复合对象优先，避免在 URL 或端点路径内再次识别 IP 或 ERROR。
- 新输出在 `onWriteParsed` 中同步应用装饰，赶在下一次绘制前完成；解析中的逐行滚动事件使用微任务合并，解析完成后取消重复更新，不按每一行输出扫描整屏。
- 按行维护装饰，只替换匹配位置或颜色变化的行；视口仍可见的行在滚动中继续复用。每行共享一个 xterm marker，避免每个匹配各自监听历史缓冲变化。
- 规则结果使用最多 256 条的 LRU 缓存，缓存键包含文本、单元格宽度、是否显式着色/反色/隐藏，确保相同文本修改 ANSI 属性后不会沿用旧高亮。尺寸、缓冲区切换、关闭和销毁时清理相应资源。
- xterm.js 5.5 原生滚轮滚动抑制公开 `onScroll` 事件，因此在 `open()` 后绑定 `.xterm-viewport` 的原生 scroll 事件，在内部视口更新后重新着色；渲染事件也核对视口位置，兼容晚挂载。
- 已识别的提示符只着色提示符部分，后面的命令输入不参与通用规则。
- 备用屏幕停用；普通屏幕中的自定义交互程序不能全部识别。完全相同的普通文本也可能被启发式规则识别。
- 不将普通数字统一视为状态码，不根据裸文件名猜测可执行权限或文件类型，不实现任意程序的完整语法解析。
- 多行提示符、跨物理行匹配、带空格或复杂转义的路径、本地化日期格式、特定命令的列级语义暂不完整支持。

## 验证

`tests/outputHighlight.test.mjs` 使用真实 xterm 解析器覆盖典型输出、中文/emoji 单元格映射、
已有颜色保护、无效 IP、规则重叠、备用屏幕、开关和解析后立即着色。
回归测试模拟 xterm 抑制公开滚动事件，并验证原生视口滚动仍会重建历史高亮及关闭时清理监听。
无头 Chrome 使用真实 xterm DOM 渲染验证连续 35 次提示符输出（含滚动），736 次提示符
颜色采样均为预期颜色，未采样到默认白色；已检查 1100px/640px 截图。
另验证 160 行历史的真实鼠标滚轮和应用滚动条所用的 `scrollToLine` 路径，历史文字颜色一致。
样例输出的 60 行规则扫描共 100 轮，中位数约 0.6ms、95 分位约 1ms，
该数字只描述规则扫描，不包含 SSH、装饰注册/清理或完整渲染开销。

### 大量输出与历史滚动

浏览器对比使用 xterm 5.5 默认 DOM 渲染器、120 列、30 行和 10000 行回滚缓冲。
以下为本机样例结果，并非完整 SSH 或 Tauri WebKit 基准：

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 200 行日志解析与高亮 | 约 2092ms | 约 3.7ms |
| 上述输出创建的装饰 | 29931 | 177 |
| 万行历史下 60 次 API 滚动更新，不含逐帧绘制 | 约 1976ms | 约 7ms |
| 上述滚动新建装饰 | 10800 | 1080 |

另使用 256 行分块持续写入十万行变化日志（含不同 PID、IP:端口/路径），
检查尾行和最后提示符完整，启用高亮约 8 秒，关闭高亮约 2.1 秒；
启用时 10ms 定时心跳最大间隔约 54ms，活动标记最多 30 个、缓存最多 256 条。
十万行输出后另通过 30 次真实鼠标滚轮操作检查历史着色，未丢失高亮，资源数量保持上述上限。
这说明高亮仍有额外成本，尤其大量可见行同时替换时，不能据此声称与关闭高亮等速。
完整 Tauri 桌面、远端 SSH 和持续大量输出的性能仍需实机验证。
