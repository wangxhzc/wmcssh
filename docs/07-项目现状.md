# wmcssh 项目现状

> 最后更新：2026-08-22
> 当前版本：0.1.1  
> 本文是项目整体能力、架构与限制的当前事实基线。实际代码、数据库迁移和
> `src-tauri/tauri.conf.json` 始终具有更高优先级。

## 1. 产品定位

wmcssh 是一款面向桌面环境的 SSH 客户端，技术栈为 Tauri 2、React、TypeScript
与 Rust。当前重点是提供轻量的主机管理、多终端会话、快捷连接、安全凭据保存和
基础 SFTP 文件传输，并保持 Linux 与 Windows 的桌面体验一致。

应用采用无系统装饰窗口，标题栏、快速连接入口、侧边栏和工作区均由前端实现。
默认窗口最小尺寸为 1280 × 720。

## 2. 当前用户界面

整体界面分为三个主要区域：

- 自定义标题栏：负责窗口拖动与窗口控制，中部提供快速连接输入框，窗口控制按钮左侧
  提供设置中心入口。
- 主机侧边栏：提供主机搜索、创建、编辑、复制、删除和右键菜单操作。
- 工作区：以标签页承载终端会话和文件传输会话，并显示连接状态与操作反馈。

界面使用统一的深色配色和集中维护的样式变量。终端使用 Maple Mono Normal NF
作为拉丁字符与图标的首选字体，并通过跨平台系统等宽字体链回退显示汉字。主题色
目前由代码定义，尚未提供面向用户的配色编辑界面。

## 3. 已实现能力

### 3.1 主机管理

- 创建、读取、更新、删除和复制 SSH 主机配置。
- 按名称或连接信息搜索主机。
- 从侧边栏打开终端或文件传输会话。
- 主机右键菜单支持全局点击、窗口失焦和 Escape 键关闭，避免菜单残留并阻断终端焦点。
- 主机记录只保存凭据引用，不保存明文密码或私钥口令。

数据库层已经包含分组、标签等相关模型，但它们尚未形成完整的前端管理流程和公开
命令能力，因此不应视为已交付的用户功能。

### 3.2 快速连接

标题栏支持下列输入形式：

```text
ssh 10.0.0.1
ssh root@10.0.0.1
ssh root@10.0.0.1:2222
```

未输入用户名时，凭据对话框默认填入当前操作系统用户名。用户可以独立选择记住
账户和密码；选择记住任一信息后，会创建或复用以主机名/IP 为名称的主机记录，
密码通过加密凭据库保存。未选择记住时，凭据只用于当前连接。

### 3.3 SSH 终端

- 支持密码与私钥认证。
- 支持同时打开多个终端标签页。
- 支持终端输入、窗口尺寸同步、断开与重连状态展示。
- 首次连接必须确认服务器主机密钥 SHA256 指纹；信任记录保存在应用数据目录的
  `known_hosts`，密钥变化时连接会被阻止并要求显式核对更新。
- 使用 xterm.js 渲染终端，高频输出直接写入终端实例，避免经过 React 状态树。
- 窗口失焦期间的终端输出会继续接收；恢复可见时先追平积压数据，再只显示最终画面，
  避免 `docker stats`、`top` 等动态命令逐帧重放历史刷新。
- 终端使用不依赖系统覆盖式滚动条的固定滚动轨道，主机侧边栏也固定预留滚动条槽位。
  终端会阻止远端清屏序列删除已有滚动历史；动态命令仍可正常清理当前画面，但不会导致
  此前的命令记录无法向上查看。
- 连接期间的短暂初始化阶段带有输入缓冲，降低刚打开会话时丢失输入的概率。
- 支持字体、字号、字重、行高、字间距、光标闪烁和回滚行数等设置数据。

当前没有终端分屏、SSH Agent、跳板机链路或面向用户的终端配色编辑器。

### 3.4 文件传输

- 每个文件传输标签页持有独立的后端 SSH/SFTP 会话。
- 文件传输与终端共用主机密钥信任规则；保存的认证信息缺失或失效时会重新请求临时凭据，
  用户仍可选择是否记住更新后的凭据。
- 支持浏览远端目录。
- 支持上传单个文件和递归上传目录。
- 支持下载单个文件和递归下载远端目录。
- 上传和下载均进入进程内后台队列，任务状态包含排队、运行、完成、失败与取消；界面可按
  字节数和文件数显示进度并取消任务。关闭文件传输标签页后，已排队或运行的任务继续执行。
- 下载由 Rust 后端流式写入用户选择的目标路径，文件或目录先写入同级暂存路径，全部成功
  后才替换目标；取消或失败会清理暂存内容并保留已有目标，不通过前端或 IPC 聚合文件内容。
- 上传同样使用远端暂存路径，取消或失败会清理未完成内容；为避免破坏已有目录，递归上传
  在同名远端目录已存在时会明确失败。
- 不同文件传输会话使用独立锁，阻塞式 SSH/SFTP 操作在后台阻塞线程执行。

当前尚未提供远端文件删除、重命名、移动、权限修改和断点续传。后台队列仅在当前应用
进程内保留，退出应用后不会恢复未完成任务。

### 3.5 设置与运行信息

标题栏提供图形化设置中心，包含常规、终端、安全和传输四个分类：

- 常规页显示应用版本、内部契约版本、当前用户和本地保存说明。
- 终端页可编辑字体、字号、字重、行高、字间距、光标闪烁和回滚行数，采用草稿、
  应用和载入默认值交互；保存后会同步应用到当前与后续终端。
- 安全页可查看、刷新和精确删除应用 `known_hosts` 中的已信任主机密钥，显示主机、
  端口、密钥类型和 SHA256 指纹；删除前需要二次确认。
- 传输页显示跨文件传输标签的进程内后台任务队列，并支持查看进度、错误和取消任务。

主题配色目前仍由代码定义。近期会话数据已有后端能力，前端尚未形成完整入口。

### 3.6 通知与交互

应用内通知用于反馈复制、连接和操作结果，并按设定时间自动消失。菜单与弹层需要同时
处理组件内部点击、全局点击、窗口失焦与键盘关闭，避免覆盖终端后留下不可见焦点层。

## 4. 系统架构

### 4.1 前端

- `src/app/`：应用装配、自定义标题栏和整体壳层。
- `src/features/`：主机、终端、文件传输、快速连接和凭据库等功能 UI。
- `src/services/tauri/`：Tauri 命令与事件的类型化封装。
- `src/stores/`：跨组件的应用状态。
- `src/types/`：前后端共享语义的 TypeScript DTO。

前端通过 Tauri 封装调用后端，不在组件中直接分散 `invoke`。终端实例由专用注册表
维护；React 只保存标签页、会话标识和可渲染状态。

### 4.2 后端

- `commands/`：暴露给前端的 Tauri 命令。
- `contracts/`：命令输入、输出及事件契约。
- `services/`：主机、近期会话、设置和文件传输等业务逻辑。
- `repositories/` 与 `db/`：SQLite 访问和迁移管理。
- `secrets/`：凭据库初始化、解锁、加密与兼容迁移。
- `ssh/`：SSH 终端会话、后台 worker 与 SFTP 生命周期。

SSH I/O 在 Rust 后台工作线程中执行，通过事件向前端传递输出和状态。终端会话与文件
传输会话分别由后端管理，前端使用会话 ID 定位资源。

## 5. 数据与安全

应用数据存放在 Tauri 应用数据目录中的 `wmcssh.sqlite`。SQLite 启用外键、WAL 模式
和忙等待超时。当前迁移包括基础业务表以及加密凭据库表。

凭据安全模型如下：

- 主机表只保存 `password_ref` 和 `passphrase_ref`。
- 密钥由主密码通过 Argon2id 派生，当前参数为 64 MiB 内存、3 次迭代、并行度 1。
- 密文使用 XChaCha20-Poly1305 与随机 nonce 加密。
- 解锁后的主密钥只存在于进程内存中，并在释放时清零。
- 主密码本身不持久化；遗忘主密码后，已加密凭据无法恢复。
- SSH 认证前校验服务器主机密钥；首次连接和密钥变化均不会静默放行。
- 初始化凭据库时可以迁移旧版明文 `wmcssh.json`，完成后删除旧文件。该文件不是当前
  正常存储路径。

应用日志存放在 Tauri 日志目录，默认文件为 `wmcssh.log`。启动时按 1 MiB 阈值轮转，
最多保留 4 个文件。任何新增日志都不得包含密码、私钥内容、口令或派生密钥。

WebView 已配置本地资源 CSP。前端文件系统权限只保留上传目录枚举所需的用户目录读取，
下载写入由 Rust 后端在用户通过原生保存/目录对话框选定目标后执行。

## 6. 数据库与兼容原则

数据库迁移是只向前执行的版本历史。已发布迁移不得重写；表结构或默认值变化必须新增
迁移，并兼顾既有用户数据。秘密值不得因方便查询而回填到主机表或普通设置表。

前后端 DTO、Tauri 命令签名和事件负载构成内部兼容边界。修改命令时需同步更新 Rust
契约、命令注册、TypeScript 类型和封装层。

## 7. 开发、验证与发布

常用验证命令：

```bash
npm run build
cd src-tauri && cargo fmt --check
cd src-tauri && cargo test
npm run tauri dev
```

项目使用 Node 内置测试运行器覆盖可独立验证的 TypeScript 逻辑，并以严格 TypeScript
构建作为基础静态检查。涉及标题栏、菜单焦点、终端输入、凭据库或文件传输的桌面行为
仍必须在 Tauri 开发模式中人工验证，单独运行 Vite 不足以覆盖这些能力。

本地脚本支持构建 Linux amd64 和 Windows amd64 包。GitHub Release 工作流在 `v*`
标签上构建 Linux DEB，以及 Windows NSIS 安装包；Windows 不再生成 MSI。`dist/`、
`src-tauri/target/` 与本地安装包均为生成产物，不应手工修改或提交。

## 8. 当前质量状态

- Rust 单元测试覆盖设置、凭据加密、主机密钥存储、传输任务状态、路径校验与暂存替换
  等关键逻辑；真实 SSH/SFTP 互操作仍需人工回归。
- Node 测试覆盖快速连接、主机密钥挑战解析、设置草稿规范化和传输进度计算；
  TypeScript 严格模式和生产构建是前端的基础静态检查。
- 桌面交互仍主要依赖手工回归，尚无端到端测试。
- CI 会执行前端测试与构建，以及 Rust 格式检查、测试和严格 Clippy；发布工作流负责打包。

## 9. 已知限制与后续重点

当前优先补齐的方向包括：

1. 扩展设置中心，提供可配置主题及更多应用级偏好。
2. 完善主机分组、标签和近期会话的用户界面。
3. 增强 SFTP 文件管理与可靠传输能力，包括删除、重命名、断点续传和跨重启任务恢复。
4. 扩展 SSH 能力，例如 Agent、跳板机、端口转发和更完整的连接诊断。
5. 增加前端单元测试与桌面端到端测试，并把构建、测试和格式检查纳入 CI。
6. 补充自动更新、崩溃诊断与更系统的发布验证。

以上条目是项目级能力缺口，不代表已承诺的版本排期。实现状态发生变化时，应在同一提交
中更新本文，避免设计文档、界面表现与实际能力长期偏离。
