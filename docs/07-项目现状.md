# wmcssh 项目现状

> 最后更新：2026-11-08
> 当前版本：0.1.2
> 本文是项目整体能力、架构与限制的当前事实基线。实际代码、数据库迁移和
> `src-tauri/tauri.conf.json` 始终具有更高优先级。

## 1. 产品定位

wmcssh 是一款面向桌面环境的 SSH 客户端，技术栈为 Tauri 2、React、TypeScript
与 Rust。当前重点是提供轻量的主机管理、多终端会话、快捷连接、安全凭据保存和
基础 SFTP 文件传输，并保持 Linux 与 Windows 的桌面体验一致。

应用采用无系统装饰窗口，标题栏、快速连接入口、侧边栏和工作区均由前端实现。
默认窗口最小尺寸为 640 × 480，启动与恢复窗口时按当前屏幕可用区域限制大小；
宽度不超过 900px 时主机侧栏以可关闭的覆盖面板呈现。侧栏右边界支持拖动调整宽度，
范围为 200px 至窗口工作区宽度的一半（最多 480px），双击边界恢复默认 240px；也可聚焦
边界后使用左右方向键调整。宽度在当前运行期间保留，重启后恢复默认。

## 2. 当前用户界面

整体界面分为三个主要区域：

- 自定义标题栏：负责窗口拖动与窗口控制，中部提供快速连接输入框，窗口控制按钮左侧
  提供设置中心入口。
- 主机侧边栏：提供主机搜索、创建、编辑、复制、删除和右键菜单操作。
- 工作区：以标签页承载终端会话和文件传输会话，并显示连接状态与操作反馈。

界面使用统一的深色配色和集中维护的样式变量。终端使用 Maple Mono Normal NF
作为拉丁字符与图标的首选字体，并通过跨平台系统等宽字体链回退显示汉字。主题色
目前由代码定义，尚未提供面向用户的配色编辑界面。
终端默认 ANSI 色板集中在 `terminalTheme.ts`，16 色各自独立，普通色与亮色分开，
紫色、青色与绿色可区分；256 色与 True Color 使用 xterm.js 原生解析和渲染。
SSH PTY 保持 `xterm-256color`，尽力发送 `COLORTERM=truecolor` 环境变量；服务器
拒绝时不阻断连接，Bash/Zsh 会话注入还会在当前 shell 内设置该变量。

## 3. 已实现能力

### 3.1 主机管理

- 创建、读取、更新、删除和复制 SSH 主机配置。
- 按名称或连接信息搜索主机。
- 从侧边栏打开终端或文件传输会话。
- 主机卡片单击选择、双击连接，右键打开连接、文件传输、编辑等操作菜单；卡片不再显示
  独立连接和更多按钮。名称与地址各占一行，过长时以省略号显示。搜索无匹配与尚未创建
  主机使用不同提示。
- 主机卡片支持拖动排序，显示插入位置，靠近列表边缘时自动滚动；Escape、窗口失焦或
  拖出列表松开可取消。排序事务性保存到现有 `hosts.sort_order`，重启后保留；搜索结果中
  拖动按目标主机的全局位置插入，不改变其他主机的相对顺序。
- 主机右键菜单支持全局点击、窗口失焦和 Escape 键关闭，避免菜单残留并阻断终端焦点。
- 主机记录只保存凭据引用，不保存明文密码或私钥口令。
- 更新凭据先写入独立的新加密引用，主机配置提交成功后再删除旧引用；配置或凭据写入
  失败时清理新引用并保留原凭据。若进程在两阶段之间退出或清理失败，可能留下不再引用
  的加密记录，当前尚无自动回收机制。

数据库层已经包含分组、标签等相关模型，但它们尚未形成完整的前端管理流程和公开
命令能力，因此不应视为已交付的用户功能。

### 3.2 快速连接

标题栏支持下列输入形式：

```text
172.16.1.1
root@172.16.1.1
root@172.16.1.1:2222
```

无须输入 `ssh` 前缀，同时兼容带此前缀的输入。输入框仅在获得焦点且为空时显示
“172.16.1.1 或 root@172.16.1.1”示例，失焦后隐藏。

未输入用户名时，凭据对话框默认填入当前操作系统用户名。用户可以独立选择记住
账户和密码；选择记住任一信息后，会创建或复用以主机名/IP 为名称的主机记录，
密码通过加密凭据库保存。未选择记住时，凭据只用于当前连接。

### 3.3 SSH 终端

- 支持密码与私钥认证。
- SSH 认证阶段等待时间至少为 60 秒（连接超时配置更大时沿用配置），以容纳服务器
  DNS/PAM 查询延迟；认证等待超时单独报告为可重试的超时错误，不显示为凭据认证失败。
- SSH TCP 连接启用 `TCP_NODELAY`，避免交互输入小包因 Nagle 合并产生额外等待。
- 支持同时打开多个终端标签页。标签字号为 12px，高度固定 25px，选中标签文字加粗。
- 标签页超出工作区宽度时隐藏横向滚动条，并在右侧提供全部标签列表用于快速切换。
- 标签页右键菜单按主机 ID 独立读取配置，复制会话和文件传输不受侧边栏搜索过滤影响；
  配置读取失败时显示错误并禁用这两项操作。
- 标签页右键“复制连接”和“文件传输”创建的新标签插入被操作标签之后，并自动激活。
- 终端和文件传输标签支持鼠标拖动混合排序，显示插入位置，靠近标签栏左右边缘时自动
  滚动；Escape、窗口失焦或拖出标签栏松开可取消。排序在本次运行期间保留，不重建会话。
- 支持终端输入、窗口尺寸同步、断开与重连状态展示。尺寸变化时保留旧画面直到重排后
  绘制，并按会话与行列数去重远端尺寸通知，减少窗口缩放时的闪动与重复刷新。
- 首次连接必须确认服务器主机密钥 SHA256 指纹；信任记录保存在应用数据目录的
  `known_hosts`，密钥变化时连接会被阻止并要求显式核对更新。
- 使用 xterm.js 渲染终端，高频输出直接写入终端实例，避免经过 React 状态树。
- 终端挂载后优先加载与 xterm 5.5 匹配的官方 WebGL 渲染器，避免密集高亮拆分大量 DOM
  文字节点后，选区变化反复重建整屏文字；显卡不支持、初始化失败或上下文丢失时回退
  默认 DOM 渲染器并禁用该终端的额外输出高亮，连接、复制与远端 ANSI 颜色仍可用。
- 远端启用全鼠标移动报告时，本地选区存在期间不转发无按键鼠标移动，避免 Shift 拖选后
  松开 Shift、轻微移动鼠标就清除选区；鼠标点击、拖动与键盘输入仍按原流程处理。
- 普通终端中 Shift+左键拖选从本次点击位置开始，不再沿用上次选区起点；远端启用鼠标
  报告时仍保留 Shift 强制本地选择。
- SSH 输出 Channel 明确使用 `sessionId`、`dataBase64` 字段，并通过序列化契约测试覆盖，
  避免已连接后因字段命名不匹配而无法显示 shell 输出。
- 前端在发起连接前生成并绑定会话 ID，后端校验 ID 并拒绝覆盖已有会话，避免快速连接或
  快速失败时丢失先于命令返回的状态事件。异步事件监听在组件清理后完成注册时立即注销。
- 长文本输入分块保留完整的 Unicode 代理对，避免补充平面字符跨块时编码失败并停止输入。
- 窗口失焦期间的终端输出会继续接收；恢复可见时先追平积压数据，再只显示最终画面，
  避免 `docker stats`、`top` 等动态命令逐帧重放历史刷新。
- 输出解析不依赖动画帧或窗口焦点，不再按字节裁掉积压输出。前端通过解析完成确认向
  Rust 释放输出额度；每个会话最多约 1 MiB 未确认数据，达到上限后暂停 SSH 读取，
  仍继续处理输入、保活和断开请求。
- 输入命令队列限制为 256 条，待发送输入总量限制为 4 MiB（包含 worker 内的数据）；
  队列满时前端按原顺序重试未接收的数据，不断开会话或虚假恢复连接状态。
- SSH 保活在正常空闲期间也按配置定期发送；worker 正常结束、失败或 panic 后均清理
  管理器中的会话句柄，主动断开不受输入队列拥塞阻塞。
- 终端使用不依赖系统覆盖式滚动条的固定滚动轨道，主机侧边栏也固定预留滚动条槽位。
  终端会阻止远端清屏序列删除已有滚动历史；动态命令仍可正常清理当前画面，但不会导致
  此前的命令记录无法向上查看。
- 连接期间的短暂初始化阶段带有输入缓冲，降低刚打开会话时丢失输入的概率。
- Linux 终端选中内容写入 PRIMARY，中键和 Shift+Insert 读取 PRIMARY；右键复制/粘贴、
  Ctrl+Shift+C/V 使用 CLIPBOARD，Ctrl+C 保留终端中断语义。PRIMARY 通过 GTK 主线程
  原生接口读写，不再依赖 WebView 默认中键粘贴；非 Linux 保留选中自动复制及中键粘贴
  常规剪贴板的行为。
- 支持远程程序通过 OSC 52 将 UTF-8 文本写入本机剪贴板（例如远程 Codex 的复制操作）；
  仅接受常规剪贴板目标，编码负载上限为 1 MiB，不响应读取本机剪贴板的查询。
- 终端快捷键、右键、中键及 WebView 原生粘贴在内容含 CR 或 LF 时先显示预览，单行
  末尾带换行同样确认；预览标明结尾换行，确认后才发送，取消或 Escape 不发送。
  普通单行直接粘贴，切换标签或重连时取消待确认内容，旧预览不会发送到新会话。
- 终端标签与标签列表仅显示连接 IP（使用域名连接时显示域名），底部状态栏显示
  “IP:端口 · 状态”。OSC 0/2 远端标题保留在标签悬停提示中，同时可查看已报告的
  当前目录；重新连接时清空旧会话的标题与目录。
- SSH 连接时通过独立 exec 通道探测登录 shell，为 Bash/Zsh 注入仅当前会话生效的
  OSC 7 提示符钩子，保留已有 `PROMPT_COMMAND` / `precmd_functions`，不修改远端文件。
  Bash 的字符串提示符钩子保持字符串；Bash 5.1 及以上对已有数组追加钩子，较旧版本
  将已有数组按顺序合并为字符串，兼容只执行 `PROMPT_COMMAND[0]` 的行为。
  `PROMPT_COMMAND` 为只读变量时跳过 Bash 目录钩子安装，保留服务器原有提示符配置，
  该会话不自动上报目录，避免初始化时触发只读变量错误。
  路径按字节进行 URI 编码，右键打开文件传输时使用最近上报的目录。探测失败、缺少
  `od`/`tr`/`sed`/`stty` 或其他 shell（包括 CMD/PowerShell）时跳过；初始化时关闭 PTY
  回显，注入完成后清除光标所在行并恢复回显，避免普通单行提示符重复，保留登录信息；
  Bash 初始化末尾会核对最近历史条目的专用标记并仅删除本次注入命令，不依赖
  `HISTCONTROL=ignorespace`，也不清理用户历史或修改其历史配置；既有污染记录不自动删除，
  Zsh 的历史污染尚未处理。多行自定义提示符仅清除最后一行。
  初始化输出过滤器仅在注入完成标记之前移除 Readline 关闭括号粘贴模式时附带的
  换行，兼容 Bash 5.3 的提示符换行行为；按流处理跨数据块控制序列，收到标记后移除
  过滤器，超过 256 KiB 未收到标记时自动停止过滤，结束会话时保留未完整匹配的字节。
  自定义启动流程切换 shell、自动进入交互程序或覆盖提示符
  钩子时不保证目录更新。已通过 Bash 5.0/5.1/5.3 的真实 SSH 输出与 xterm.js 解析
  验证单行提示符及目录上报；完整 Tauri 桌面交互和 Zsh 仍需实机验证。
- OSC 8 超链接和普通 HTTP/HTTPS 网址支持 Ctrl/Cmd+单击，通过系统默认浏览器打开；
  前后端均限制协议并拒绝含账户密码的链接，不在 WebView 内导航。
- OSC 9 文本通知与 OSC 777 `notify;标题;正文` 显示应用内通知，可点击切换到来源标签，
  8 秒后自动关闭；全局每秒最多接收一条，相同来源和内容 10 秒内去重，最多展示三条。
  窗口处于后台时请求系统任务栏提醒，不自动抢占焦点；尚无系统通知中心集成。
- OSC 7 `file://远端主机/绝对路径` 记录远端工作目录；从终端标签右键打开文件传输时，
  新文件页以该目录为起点，已有文件页不随终端切换目录。需要远端 shell 主动报告 OSC 7，
  未报告时沿用文件页默认目录；路径仅用于原主机的 SFTP，不作为本机路径打开。
- 鼠标报告模式下按滚轮实际行数发送报告，修正 xterm.js 5.5 将多行滚动压成一次报告的行为；
  像素滚动按终端行高累计，单次最多发送 32 条，普通回滚与 Shift/Ctrl/Cmd 滚轮沿用原逻辑。
- 支持字体、字号、字重、行高、字间距、光标闪烁和回滚行数等设置数据。首次挂载终端及
  应用字体设置前显式等待所需字体加载，避免按回退字体测量导致字距和光标异常变宽。

当前没有终端分屏、SSH Agent、跳板机链路或面向用户的终端配色编辑器。

设置中心提供默认关闭的“输出高亮”，持久化后应用于现有和新建终端。
基于 xterm.js proposed Decoration API 对可见行中的日志级别、常见错误短语、服务/容器/
网络状态、IPv4/IPv6/CIDR、IP:端口/路径（含带括号 IPv6、localhost/域名端点）、
MAC、UUID、日期时间、路径/URL、文件权限、容量/耗时、
HTTP 方法/状态码、百分比和部分键值进行客户端着色；使用率仅在 `df` 行及
usage/used/utilization 标签后按 80%/90% 分级，丢包率单独处理，普通百分比保持中性色。
URL 按通用 `协议://` 结构识别，覆盖 HTTP(S)、FTP(S)、SOCKS、SSH/SFTP 等；
协议前缀和端口为灰色、主机为青色、路径/查询为蓝色，仅影响补色，不扩展可点击协议。
端口、时间戳、容量和 PID 等元数据统一使用中性灰，降低密集输出的彩色干扰。
支持行首 `[用户@主机 目录]#/$` 与 `用户@主机:目录#/$`
常见提示符，未着色的 root 用户名为红色、普通用户名和主机为绿色、目录为蓝色。
不改变 SSH 数据或复制内容；已有前景/背景色、反色和隐藏文字
保持原样，备用屏幕中停用。新输出在解析完成后同步应用高亮，避免先白后彩；
解析期间逐行滚动事件合并到解析完成或微任务中处理，原生视口/API 滚动在绘制前更新，
兼容 xterm.js 5.5 滚轮不触发公开 `onScroll` 的行为。按行复用未变化的装饰，
同一行的匹配共享一个标记，规则结果按文本、单元格宽度与样式缓存，最多 256 条；
每行最多 32 处、可见区域最多 300 处，
重叠规则按优先级只采用一处，已识别提示符后的输入保持原样。
输出高亮仅在 WebGL 渲染可用时生效，跨页拖选持续更新高亮，新滚入行无需等到松手才着色，
不再通过暂停高亮更新保护 DOM 拖选。渲染模式按终端独立跟踪，上下文丢失后立即清理
该终端的额外高亮，不影响其他 WebGL 终端。所有已检测终端均无 WebGL 时，设置中心
将高亮开关显示为不可用；保存的偏好保留，后续 WebGL 会话按偏好应用。
原有 ANSI 色与复制内容不变。
跨物理换行的匹配暂不支持；已通过浏览器十万行变化日志与万行历史滚动压力验证，
完整 Tauri/SSH 场景的吞吐与延迟仍需实机验证。
规则资料、范围与限制见 [`08-终端输出高亮.md`](08-终端输出高亮.md)。

### 3.4 文件传输

- 每个文件传输标签页持有独立的后端 SSH/SFTP 会话。
- 文件页在连接完成前关闭时，迟到的 SFTP 会话会主动释放，不再遗留后台连接。
- 文件传输与终端共用主机密钥信任规则；保存的认证信息缺失或失效时会重新请求临时凭据，
  用户仍可选择是否记住更新后的凭据。
- 支持浏览远端目录；地址栏可直接编辑路径并按 Enter 跳转，支持绝对路径及相对于当前目录的
  路径，Escape 恢复当前目录路径。跳转失败时保留原目录列表，并可修改路径重试。
- 单选普通文件或目录时，右键菜单支持重命名。弹窗预填原名称，支持 Enter 提交、
  Escape 取消及失败后重试；名称不能为空、`.`、`..` 或包含路径分隔符、空字符。
  后端仅在原父目录内重命名，拒绝覆盖已有条目，会话忙时提示重试；成功后刷新并选择新名称。
- 文件列表右键菜单支持删除单选或多选条目，执行前通过原生弹窗确认；目录递归删除，
  符号链接仅删除链接本身。单个条目删除前预检目录树（默认最多 1000 个条目、10 层子目录），
  会话忙时提示重试。批量操作反馈成功数量及失败项，完成后刷新目录；删除不可撤销，
  运行中失败可能留下部分已删除的目录内容。
- 刷新或导航失败时保留原目录列表与路径，重试使用失败时的目标路径；文件大小使用易读
  单位（零字节显示为 0 B）。单击选中，双击目录进入；Ctrl/Cmd 切换多选，Shift 选择范围，
  Ctrl/Cmd+A 全选，Escape 或点击空白取消选择；方向键、Home/End 移动选择，Enter 进入目录。
  刷新保留仍存在条目的选择，切换目录后清空。右键已选项保留多选，右键未选项改为单选。
  工具栏与右键菜单支持下载所选项及右键复制多个路径；批量下载只选择一次本地目标目录。
  条目采用 30px 紧凑行高与 12px 字号，下载入口集中在工具栏和右键菜单。
- 支持上传单个文件和递归上传目录。
- 支持从系统文件管理器拖入多个本地文件或文件夹，上传到松手时当前文件页的远端目录，
  复用后台队列、递归目录限制与完成后刷新。只有活动且就绪的文件页接收拖放，弹窗打开时
  不接收；不支持拖入符号链接。拖入路径由 Tauri 动态授予读取范围，无需开放整个文件系统。
- 支持下载单个文件和递归下载远端目录。
- 普通文件支持右键“打开”及双击打开：后端校验文件类型和大小，仅允许小于等于
  10 MiB（10 × 1024 × 1024 字节）的文件，超限提示文件太大；下载期间也检查实际字节数。
  文件流式下载到应用缓存目录 `opened-files` 下的独立临时目录，保留原文件名和扩展名，
  完成后使用系统默认程序打开。失败时清理临时副本，成功副本保留以供外部程序使用，
  在后续打开操作时清理超过 7 天的旧目录。本地编辑不会自动回传；不支持打开符号链接。
  打开为前台操作，下载期间当前标签页暂停其他操作，会话忙时提示稍后重试。
- 上传与普通下载均进入进程内后台队列，任务状态包含排队、运行、完成、失败与取消；界面可按
  字节数和文件数显示进度并取消任务。关闭文件传输标签页后，已排队或运行的任务继续执行。
- 文件页队列面板位于文件列表下方，任务采用紧凑间距，默认高度 180px；顶部边界支持拖动
  和上下方向键调整高度，双击恢复默认，最大高度为文件页的 60%。展开不改变文件列表
  顶部位置。自动展开的队列在全部任务完成或取消后 3 秒自动收起，手动展开则保持展示，
  直到用户手动关闭；失败任务保留展示。操作与目录状态提示在底部悬浮显示，不占用列表布局；
  操作提示淡入淡出，5 秒后消失，需处理的目录错误保留操作入口。已结束任务支持手动删除记录，成功记录在
  完成 60 秒后由后台自动清理，失败与取消记录保留到手动删除或退出应用。
  删除记录不会删除已传输文件。记录上限默认为 200，达到上限需清理记录后再提交任务。
  上传完成后，待当前会话的传输队列空闲时自动刷新当前目录；非活动标签在切回后刷新。
- 下载由 Rust 后端流式写入用户选择的目标路径，文件或目录先写入同级暂存路径，全部成功
  后才替换目标；取消或失败会清理暂存内容并保留已有目标，不通过前端或 IPC 聚合文件内容。
- 上传同样使用远端暂存路径，取消或失败会清理未完成内容；为避免破坏已有目录，递归上传
  在同名远端目录已存在时会明确失败。
- 不同文件传输会话使用独立锁，阻塞式 SSH/SFTP 操作在后台阻塞线程执行。
- 传输使用固定 4 个 worker，同一会话按提交顺序执行，等待任务不再各占一个线程；
  调度队列默认最多保留 200 个等待任务，与配置的任务记录上限一致。目录读取遇到会话忙时立即提示稍后刷新。
- 通过窗口关闭按钮或系统关闭窗口时，如有终端会话（含连接中）、已建立的文件会话，
  或排队、运行中的传输，统一弹窗列出数量，确认后才退出；取消则保留窗口和连接。
  无会话和未完成任务时直接关闭，无法读取会话或任务状态时也要求确认。

当前尚未提供远端文件移动、权限修改和断点续传。后台队列仅在当前应用
进程内保留，退出应用后不会恢复未完成任务。

#### 文件传输限制配置

应用首次启动会在应用数据目录自动生成 `transfer-config.json`，修改后重启生效。
Linux 默认路径为 `~/.local/share/com.example.wmcssh/transfer-config.json`
（设置 `XDG_DATA_HOME` 时使用该目录），Windows 为
`%APPDATA%\com.example.wmcssh\transfer-config.json`。

```json
{
  "maxDirectoryFiles": 1000,
  "maxDeleteEntries": 1000,
  "maxDirectoryDepth": 10,
  "maxRetainedTasks": 200
}
```

- `maxDirectoryFiles`：每个上传或下载目录任务包含的文件数量上限，不计目录。
- `maxDeleteEntries`：每个选中删除条目的递归条目上限，包含被选目录本身、文件、子目录和链接。
- `maxDirectoryDepth`：目录递归深度限制，同时用于上传、下载、删除；上传按相对路径
  段数检查（包含文件名），下载和删除以所选目录为第 0 层。
- `maxRetainedTasks`：全部文件页共享的任务记录及等待队列上限，一个目录任务算一条记录。

所有值必须是正整数，深度范围为 1–128。缺省字段使用上述默认值；无效 JSON、未知字段
或非法数值会阻止启动，并在启动错误中指出配置文件路径。前端目录扫描从后端读取同一份配置。
提高限制会增加目录扫描、删除预检及任务记录的内存和耗时。配置不包含认证凭据，
不会修改 SQLite 中的终端设置；设置中心暂不提供这些限制的编辑入口。

## 4. 系统架构

### 4.1 前端

- `src/app/`：应用装配、自定义标题栏和整体壳层。
- `src/features/`：主机、终端、文件传输、快速连接和凭据库等功能 UI。
- `src/services/tauri/`：Tauri 命令与事件的类型化封装。
- `src/stores/`：跨组件的应用状态。
- `src/types/`：前后端共享语义的 TypeScript DTO。

前端通过 Tauri 封装调用后端，不在组件中直接分散 `invoke`。终端实例由专用注册表
维护；React 只保存标签页、会话标识和可渲染状态。

### 4.2 后端

- `commands/`：暴露给前端的 Tauri 命令。
- `contracts/`：命令输入、输出及事件契约。
- `services/`：主机、近期会话、设置和文件传输等业务逻辑。
- `repositories/` 与 `db/`：SQLite 访问和迁移管理。
- `secrets/`：凭据库初始化、解锁、加密与兼容迁移。
- `ssh/`：SSH 终端会话、后台 worker 与 SFTP 生命周期。

SSH I/O 在 Rust 后台工作线程中执行，通过事件向前端传递输出和状态。终端会话与文件
传输会话分别由后端管理，前端使用会话 ID 定位资源。

SSH/SFTP 统一使用 `ssh2 → libssh2 → OpenSSL`，Linux 与 Windows 均启用
`vendored-openssl`，从源码构建由同一份 `src-tauri/Cargo.lock` 固定版本的 OpenSSL；
Windows 显式启用 `openssl-on-win32`，不再使用默认的 Windows CNG 后端。
构建环境不要设置 `OPENSSL_NO_VENDOR` 或 `LIBSSH2_SYS_USE_PKG_CONFIG` 来绕过该配置。

## 5. 数据与安全

应用数据存放在 Tauri 应用数据目录中的 `wmcssh.sqlite`。SQLite 启用外键、WAL 模式
和忙等待超时。当前迁移包括基础业务表以及加密凭据库表。

凭据安全模型如下：

- 主机表只保存 `password_ref` 和 `passphrase_ref`。
- 密钥由主密码通过 Argon2id 派生，当前参数为 64 MiB 内存、3 次迭代、并行度 1。
- 密文使用 XChaCha20-Poly1305 与随机 nonce 加密。
- 解锁后的主密钥只存在于进程内存中，并在释放时清零。
- 主密码本身不持久化；遗忘主密码后，已加密凭据无法恢复。
- SSH 认证前校验服务器主机密钥；首次连接和密钥变化均不会静默放行。
- 初始化凭据库时可以迁移旧版明文 `wmcssh.json`，完成后删除旧文件。该文件不是当前
  正常存储路径。

应用日志存放在 Tauri 日志目录，默认文件为 `wmcssh.log`。启动时按 1 MiB 阈值轮转，
最多保留 4 个文件。任何新增日志都不得包含密码、私钥内容、口令或派生密钥。

WebView 已配置本地资源 CSP。前端文件系统权限用于上传目录枚举和拖入路径类型检查，
读取范围包含用户目录及原生选择或拖入时动态授权的路径，
下载写入由 Rust 后端在用户通过原生保存/目录对话框选定目标后执行；打开远端文件时，
后端只写入应用管理的临时缓存目录，再交给系统默认程序。

## 6. 数据库与兼容原则

数据库迁移是只向前执行的版本历史。已发布迁移不得重写；表结构或默认值变化必须新增
迁移，并兼顾既有用户数据。秘密值不得因方便查询而回填到主机表或普通设置表。

前后端 DTO、Tauri 命令签名和事件负载构成内部兼容边界。修改命令时需同步更新 Rust
契约、命令注册、TypeScript 类型和封装层。

## 7. 开发、验证与发布

常用验证命令：

```bash
npm run build
cd src-tauri && cargo fmt --check
cd src-tauri && cargo test
npm run tauri dev
```

颜色回归包含在 `npm test` 中，覆盖 16 色唯一性、亮色亮度、彩色文字对背景的对比度、
ANSI/256 色前景与背景索引、True Color RGB 和颜色重置。可在待验证的远端终端运行
`scripts/terminal-colors.sh` 的内容查看实际色板；自动解析测试不替代 Tauri/SSH 实机验收。

项目使用 Node 内置测试运行器覆盖可独立验证的 TypeScript 逻辑，并以严格 TypeScript
构建作为基础静态检查。涉及标题栏、菜单焦点、终端输入、凭据库或文件传输的桌面行为
仍必须在 Tauri 开发模式中人工验证，单独运行 Vite 不足以覆盖这些能力。

生产构建将 React 和 xterm.js 库拆为独立资源块，便于应用代码更新时复用库资源缓存；
这些库仍在启动时加载，尚未实现终端库按需加载。

本地脚本支持构建 Linux amd64 和 Windows amd64 包。GitHub Release 工作流在 `v*`
标签上构建 Linux DEB，以及 Windows NSIS 安装包；Windows 不再生成 MSI。`dist/`、
`src-tauri/target/` 与本地安装包均为生成产物，不应手工修改或提交。

Windows 本地开发、打包与 Release 工作流统一使用 GNU：Rust 工具链为
`stable-x86_64-pc-windows-gnu`，目标为 `x86_64-pc-windows-gnu`，并使用
MSYS2 MINGW64 提供的 MinGW-w64 GCC。日常质量 CI 目前仍只在 Linux 上运行，
Windows 原生功能回归尚需实机或虚拟机验证。

OpenSSL 源码构建需要 C 编译器、Perl 和 Make；Linux 使用 `build-essential` 与
`perl`，Windows 的 MSYS2 MINGW64 使用 `mingw-w64-x86_64-gcc`、
`perl` 和 `make`，并将 `mingw64/bin` 与 MSYS2 的 `usr/bin`
加入构建进程 PATH。通过 `OPENSSL_SRC_PERL` 显式指定 MSYS2 `usr/bin/perl.exe`，
OpenSSL 的 `mingw64` 构建要求 Perl 生成 Unix 路径，不能使用原生 Windows 的 MINGW64 Perl。
发布构建使用 `--locked`，避免两端独立解析出不同依赖版本。

Windows GNU 的库测试显式链接 Tauri 生成的资源 manifest，确保测试程序加载 Common
Controls v6；主机密钥文件刷盘使用可写句柄，满足 Windows 的 `FlushFileBuffers` 要求。
国内网络下若打包工具下载超时，可在构建进程设置 `HTTP_PROXY` / `HTTPS_PROXY` 指向
本机实际启用的系统代理；不需要修改项目或全局代理配置。

## 9. 已知限制与后续重点

当前优先补齐的方向包括：

1. 扩展设置中心，提供可配置主题及更多应用级偏好。
2. 完善主机分组、标签和近期会话的用户界面。
3. 增强 SFTP 文件管理与可靠传输能力，包括移动、权限修改、断点续传和跨重启任务恢复。
4. 扩展 SSH 能力，例如 Agent、跳板机、端口转发和更完整的连接诊断。
5. 增加前端单元测试与桌面端到端测试，并把构建、测试和格式检查纳入 CI。
6. 补充自动更新、崩溃诊断与更系统的发布验证。

以上条目是项目级能力缺口，不代表已承诺的版本排期。实现状态发生变化时，应在同一提交
中更新本文，避免设计文档、界面表现与实际能力长期偏离。
